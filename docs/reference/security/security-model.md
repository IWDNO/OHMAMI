# Модель безопасности OHMAMI

Этот документ описывает архитектуру безопасности системы OHMAMI, механизмы контроля доступа и защиты данных.

> **Важно**: OHMAMI предоставляет удалённый доступ к компьютеру. Используйте систему только в доверенных сетях и с надлежащими мерами безопасности.

## Обзор безопасности

Система OHMAMI состоит из двух основных компонентов:

1. **Мобильное приложение** (Flutter) — клиент для управления
2. **Агент на ПК** (.NET) — серверная часть с доступом к системе

Оба компонента работают в локальной сети и не требуют внешних серверов.

> **Примечание**: В текущей версии система не использует шифрование трафика. Рекомендуется использовать только в доверенных локальных сетях.

## Компоненты системы безопасности

### 1. Блокировка приложений и процессов

Система позволяет блокировать запуск определённых приложений и доступ к файлам/папкам.

#### Механизм блокировки приложений

Блокировка реализована через несколько компонентов:

- **`AclManager`** — управление списками контроля доступа (ACL) Windows
- **`BlocklistStore`** — хранение списка заблокированных путей
- **`ProcessBlockerHostedService`** — мониторинг и автоматическое завершение заблокированных процессов

#### Как работает блокировка

1. **Добавление в блок-лист**: При блокировке приложения через API (`POST /security/block/app`) путь нормализуется и добавляется в `BlocklistStore`
2. **Применение ACL**: `AclManager` применяет правило Deny на файл исполняемого файла через Windows ACL
3. **Мониторинг процессов**: `ProcessBlockerHostedService` отслеживает запуск процессов через WMI (`Win32_ProcessStartTrace`)
4. **Автоматическое завершение**: Если заблокированный процесс пытается запуститься, он немедленно завершается

**Пример блокировки приложения**:

```json
POST /security/block/app?path=C:\Program Files\App\app.exe
```

После этого:
- Файл `app.exe` получает правило Deny на выполнение для текущего пользователя
- Путь сохраняется в `%ProgramData%\OhmamiAgent\blocklist.json`
- При попытке запуска процесс будет автоматически завершён

> **⚠️ Внимание**: Блокировка применяется только для текущего пользователя Windows. Другие пользователи могут запустить приложение, если у них есть права.

#### Блокировка путей (файлов и папок)

Блокировка путей работает аналогично, но применяет правило Deny на чтение/модификацию:

- Для **файлов**: блокируется право `Modify`
- Для **папок**: блокируется право `Modify` с наследованием для всех файлов и подпапок

**Пример блокировки папки**:

```json
POST /security/block/path?path=C:\Users\BlockedFolder
```

#### Разблокировка

Для разблокировки используется эндпоинт `DELETE /security/unblock?path={path}`, который:
1. Удаляет правило Deny из ACL файла/папки
2. Удаляет путь из `BlocklistStore`

### 2. Блокировка веб-сайтов

Система позволяет блокировать доступ к веб-сайтам через файл `hosts` Windows.

#### Механизм блокировки сайтов

Блокировка реализована через класс **`HostsManager`**, который:

1. **Модифицирует файл hosts**: Добавляет записи вида `127.0.0.1 domain.com` в файл `C:\Windows\System32\drivers\etc\hosts`
2. **Использует маркеры**: Блокированные сайты помечаются специальными маркерами:
   ```
   # BEGIN OHMAMI BLOCKED SITES
   127.0.0.1 example.com
   127.0.0.1 blocked-site.com
   # END OHMAMI BLOCKED SITES
   ```
3. **Нормализует домены**: Автоматически удаляет протоколы (`http://`, `https://`), префикс `www.` и пути

#### Требования

> **⚠️ Требования**: Для блокировки сайтов необходимы **права администратора**, так как файл `hosts` защищён системой.

**Пример блокировки сайта**:

```json
POST /security/block-site?domain=example.com
```

После этого все запросы к `example.com` будут перенаправляться на `127.0.0.1` (localhost), что эффективно блокирует доступ к сайту.

#### Разблокировка сайтов

Для разблокировки используется эндпоинт `DELETE /security/unblock-site?domain={domain}`, который удаляет соответствующую запись из файла `hosts`.

---

### 3. Хранение данных блокировки

#### BlocklistStore

Список заблокированных приложений и путей хранится в файле:

```
%ProgramData%\OhmamiAgent\blocklist.json
```

**Формат файла**:

```json
[
  "C:\\Program Files\\BlockedApp\\app.exe",
  "C:\\Users\\BlockedFolder"
]
```

> **Примечание**: Файл хранится в общей папке приложения, доступной для всех пользователей.

#### HostsManager

Список заблокированных сайтов хранится непосредственно в файле `hosts` Windows с использованием маркеров для идентификации секции OHMAMI.

## Уровни доступа

### Обычный пользователь

С правами обычного пользователя можно:

- ✅ Блокировать/разблокировать приложения и пути (только для текущего пользователя)
- ✅ Просматривать список заблокированных ресурсов
- ❌ Блокировать веб-сайты (требуются права администратора)

### Администратор

С правами администратора можно:

- ✅ Все действия обычного пользователя
- ✅ Блокировать/разблокировать веб-сайты через файл `hosts`

## Безопасность сети

### Текущие ограничения

В текущей версии системы:

- ❌ **Нет шифрования трафика** — все данные передаются в открытом виде
- ❌ **Нет аутентификации** — любой, кто знает IP-адрес и порт, может подключиться
- ❌ **Нет авторизации** — нет проверки прав доступа

> **⚠️ Критично**: Используйте систему **только в доверенных локальных сетях**. Не используйте через публичный интернет без дополнительных мер безопасности (VPN, туннелирование и т.д.).

### Рекомендации по безопасности

1. **Используйте локальную сеть**: Подключайтесь только в пределах доверенной Wi-Fi сети
2. **Настройте брандмауэр**: Ограничьте доступ к порту агента только с доверенных IP-адресов
3. **Используйте VPN**: При необходимости доступа через интернет используйте VPN-туннель
4. **Регулярно обновляйте**: Следите за обновлениями системы безопасности

## Приватность данных

### Какие данные собираются

Система собирает и передаёт следующие данные:

| Тип данных | Где используется | Хранится ли |
|------------|------------------|-------------|
| Метрики системы (CPU, GPU, память) | WebSocket, отображение в приложении | Нет (только в реальном времени) |
| Информация о медиа (название трека, исполнитель) | WebSocket, отображение в приложении | Нет |
| Список приложений | HTTP API, отображение в приложении | Нет |
| Список файлов | HTTP API, проводник в приложении | Нет |
| Список заблокированных ресурсов | Локальное хранилище на ПК | Да (в `blocklist.json`) |

### Где хранятся данные

- **На ПК**: Список заблокированных ресурсов хранится в `%ProgramData%\OhmamiAgent\blocklist.json`
- **На телефоне**: Данные не сохраняются локально (кроме кэша приложения)
- **На серверах**: Данные не передаются на внешние серверы

> **Важно**: Все данные остаются в локальной сети и не передаются третьим лицам.

## Ограничения и известные проблемы

### Ограничения блокировки приложений

1. **Только для текущего пользователя**: Блокировка применяется только для пользователя, под которым запущен агент
2. **Не блокирует системные процессы**: Некоторые системные процессы могут обойти блокировку
3. **Требует запущенного агента**: Блокировка работает только пока агент запущен

### Ограничения блокировки сайтов

1. **Требует прав администратора**: Необходимо запускать агент с правами администратора
2. **Может конфликтовать с VPN**: Некоторые VPN-сервисы могут обходить блокировку через файл `hosts`
3. **Не блокирует IP-адреса**: Блокируется только доменное имя, прямой доступ по IP возможен
