## Структура Flutter-приложения OHMAMI

Здесь описывается организация кода Flutter-клиента OHMAMI.

### Общая структура проекта

- `lib/`
  - `main.dart` — точка входа приложения.
  - `core/` — базовые сервисы, конфигурация, DI.
  - `features/` — функциональные модули (home, files, media, streaming и т.п.).
  - `widgets/` — общие переиспользуемые виджеты.
  - `data/` — слои работы с сетью и локальным хранилищем.

### Подход к архитектуре

- Чёткое разделение **presentation / domain / data** (или выбранный тобой паттерн).
- Использование стейт-менеджмента (Bloc, Riverpod, Provider и т.п. — укажи фактический вариант).
- Выделение интерфейсов для абстракций над платформенными API и сетью.

Если ты только начинаешь, удобно опираться на официальную [документацию Flutter](https://docs.flutter.dev) и гайды по архитектуре, а затем адаптировать их под особенности OHMAMI.

### Взаимодействие с агентом и сервером

- Клиенты HTTP и WebSocket вынесены в отдельные сервисы.
- Слои `repository/usecase` инкапсулируют протоколы и маппинг DTO в доменные модели.
