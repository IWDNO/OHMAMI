## Архитектура системы OHMAMI

Этот документ даёт обзор архитектуры системы OHMAMI на высоком уровне.

### Основные компоненты

- **Мобильное приложение** — клиент на Android, устанавливаемый на телефон пользователя.
- **Агент на ПК** — десктопное приложение, обеспечивающее связь с телефоном.
- **Серверная часть** (если есть) — отвечает за маршрутизацию, авторизацию, push‑уведомления и др.

В минимальной офлайн‑конфигурации может использоваться только связка *мобильное приложение ↔ агент на ПК* без обязательного сервера — это удобно для локальных сценариев и отладки.

### Потоки данных

- Сообщения управления и события (подключение, состояние устройства).
- Потоки медиа (стриминг экрана, аудио).
- Операции с файлами (загрузка/выгрузка).

### Протоколы и взаимодействие

- HTTP/REST для конфигурации и отдельных операций.
- WebSocket (или аналог) для постоянного двунаправленного соединения и событий в реальном времени.

#### Сводка по компонентам

| Компонент          | Основная роль                           | Тип связи              |
|--------------------|------------------------------------------|------------------------|
| Мобильное приложение | Источник данных, UI на телефоне        | HTTP, WebSocket        |
| Агент на ПК        | Прокси между телефоном и ПК, локальный UI | HTTP, WebSocket, IPC |
| Сервер             | Централизованные сервисы, маршрутизация | HTTPS, WebSocket       |

Подробнее о протоколах см. раздел [HTTP API агента](../reference/api/http.md) и [WebSocket протокол](../reference/api/websocket.md).
